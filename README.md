## 进程管理

### 进程与线程

1. 进程的基本概念：
   - 进程是一次程序的执行
   - 是一个程序及其数据在处理机上顺序执行时发生的活动
   - 是一个拥有独立功能的程序在数据集合上运行的过程，是系统分配资源和调度的一个独立单位
2. 进程的基本特性：
   - 动态性：具有动态的地址空间，地址空间上包括代码、数据和系统控制信息
   - 并发性：多个进程在同一时刻开始发生
   - 独立性：各进程地址空间相互独立（eg.全局变量可同时在两个进程中使用）
   - 异步性：进程会停停走走
3. 进程的组成
   - 进程控制块，即PCB
     - 进程描述信息
     - 进程控制和管理信息
     - 资源分配清单
     - 处理机相关信息
   - 程序段
   - 数据段
4. 进程的状态与转换
   - 进程的三种状态：就绪、阻塞、运行
   - 三种基本状态的转换：
     - 就绪状态到运行状态（进程调度）
     - 运行状态到阻塞状态（I/O请求）
     - 阻塞状态到就绪状态（I/O完成）
     - 运行状态到就绪状态（时间片完）
   - 创建态与终止态
     - 创建状态：限制进程数量
     - 终止状态：便于其他应用统计分析操作系统的性能
   - 挂起操作的引入
     - 终端用户的需要
     - 父进程请求
     - 符合调节的需要
     - 操作系统的需要
5. 进程控制
   - 原语操作，一般通过屏蔽中断来完成，是最小的操作
   - 进程的创建：
     - 申请空白PCB
     - 为新进程分配其运行所需资源
     - 初始化PCB
     - 如果进程就绪队列能加入新进程则加入
   - 进程的终止：
     - 正常结束、异常结束、外界干预
     - 根据被终止进程的标识符，从PCB集合中检索出该进程的PCB，从中读出该进程的状态
     - 若为执行态则立刻终止
     - 若该进程还有子孙进程，则终止其子孙进程（特例：孤儿进程）
     - 将被终止的进程的资源火归还给其父程序，或归还给系统
     - 将被终止的进程的PCB从PCB集合中移出
     - 系统调用：exit()终止进程，wait()调用该函数的进程等到子进程退出时才继续运行
     - 僵尸进程：子进程退出但是父进程未收回其PCB
     - 孤儿进程：父进程终止但是子进程还在运行
   - 进程的阻塞：
     - 阻塞原因：申请资源失败、等待操作完成、数据未到达、等待新任务到达
     - 立即停止执行，在PCB中将进程状态改为阻塞，将该PCB插入阻塞队列
   - 进程的唤醒：
     - 把被阻塞的进程从阻塞队列中移除
     - 将PCB中进程状态改为就绪
     - 将PCB插入就绪队列中
6. 进程通信：
   - 进程通信是指进程之间的信息交换
   - 低级通信：进程的同步和互斥（pv操作）
   - 高级通信：共享内存、消息传递以及管道机制
7. 线程：
   - 作为调度和分配的基本单位，一个进程可以拥有多个线程
   - 线程本身并不拥有系统资源，只拥有必不可少的保持独立运行的资源
   - 线程运行三态类似进程，线程拥有线程控制块TCB
8. 线程的实现方式：
   - 内核支持线程，利用系统调用实现
   - 用户级线程，在用户空间实现，与内核无关
   - 二者组合方式
   - 多线程模型

### 处理机调度

1. 调度基本概念
   - 作业：批处理系统中，作业作为基本单位从外村调入内存
   - 作业步：对作业的每一个加工步骤称为作业步
   - 作业控制块JCB：包含作业标识、用户名称、作业类型等
   - 处理机调度：就绪队列按照一定算法算法选择一个进程并将处理机分配给它运行
   - 调度层次：
     - 作业调度，高级调度
     - 内存调度，中级调度
     - 进程调度，低级调度
2. 调度时机和切换的情况
   - 不能进行调度和切换的情况
     - 处理中断中
     - 进程在操作系统内核程序临界中
     - 其他需要屏蔽的原子操作过程中
   - 应该调度与切换的情况
     - 发生引起调度的情况并且程序无法进行下去时
     - 中断处理或自陷处理结束后，返回被中断进程的用户态程序执行现场前
   - 调度时机
     - 正在运行的进程运行完毕或者发生某事不再继续运行，运行的过程中因输入输出请求而暂停运行
     - 在进程通信或同步过程中运行某种原语操作
     - 在可抢占式调度中有一个优先级更高的进程进入就绪队列；时间片轮转法中时间片用完
   - 进程调度的任务
     - 保存处理机的现场信息
     - 按某种算法选取进程
     - 把处理器分配给进程
3. 调度机制的基本部分
   - 排队器
     - 将就绪进程加入就绪队列
   - 分派器
     - 调度程序选出进程后分派器取出进程并将处理机分配给这个进程
   - 上下文切换器
     - 正在运行的进程和分派器程序的切换
     - 分派程序和新选出的进程之间的切换
4. 闲逛进程
   - 不执行磁盘上的任何程序，类似于链表头节点，就绪队列空闲则闲逛进程进入就绪队列以在系统闲置时减少电力消耗和热量产生
5. 上下文及其机制
   - 上下文：cpu寄存器和程序计数器PC是cpu运行任何程序时必须依赖的两个环境，被称为上下文
   - 上下文切换：
     - 将一个cpu的上下文保存起来，然后加载新任务的上下文到寄存器和程序计数器中
     - 最后跳转到程序计数器的新位置运行新任务
     - 被保存的上下文会存储到系统内核中，等任务重新调度执行时再加载进来
   - 上下文切换种类
     - 进程上下文切换：
       - 发生在内核态，由内核管理和调度
     - 线程上下文切换
     - 中断上下文切换
6. 调度基本准则
   - 处理机调度算法的共同目标
     - $`cpu的利用率=\frac{cpu有效工作时间}{cpu有效工作时间+cpu空闲等待时间}`$
     - 公平性：是否会发生饥饿现象
     - 平衡性：使系统中的cpu和各种外部设备都能经常处于忙碌状态
     - 策略强制执行
     - 周转时间=等待时间+执行时间
7. 典型调度算法
   - 先来先服务算法FCFS
     - 就绪队列里先到的进程先执行
     - 算法简单
     - 有利于cpu繁忙型作业，不利于IO繁忙型作业
   - 短作业优先调度算法SJF
     - 作业越短优先级越高
     - 平均周转时间最小，吞吐量最大
     - 对长作业非常不利，可能会导致饥饿
   - 优先级调度算法PSA
     - 高响应比优先调度算法HRRN
       - $`优先权=\frac{等待时间+要求服务时间}{要求服务时间}`$
       - 优先权越大，优先级越高
         - 有利于短作业，长作业也不会饥饿
   - 时间片轮转调度算法RR
     - 系统按照FCFS排成一个就绪队列，每隔一段时间就产生一次中断，把cpu分给队首进程并执行一个时间片。
     - 确保每一个进程轮流进行
     - 频繁的进程切换会造成额外的上下文开销
   - 多级反馈队列调度算法
     - 设置多个就绪队列，每个就绪队列使用FCFS策略，按队列优先级调度
     
## 死锁

### 死锁的概念

1. 资源问题：

   - 可重用资源与消耗性资源
   - 可抢占资源与不可抢占资源

2. 计算机系统中的死锁

   - 竞争不可抢占资源引发的死锁
   - 竞争可消耗性资源引发的死锁
   - 进程推进顺序不当引发的死锁

3. 死锁的定义

   - 多个进程因竞争资源而造成的一种僵局，若无外力作用，这些进程都无法继续向前推进

4. 产生死锁的条件

   - 互斥条件：某种资源只能被一个进程占用，其他进程想使用只能等到该资源释放（<font color=red>不可被改变</font>）
   - 不剥夺（不抢占）条件：进程获得资源在执行过程中不能被别的进程抢占资源，只能在该进程结束后自动释放资源
   - 请求并保持条件：进程占有至少一个资源后还提出新的资源请求，而请求的资源被另一个程序占用，此时请求进程被阻塞，同时进程对自己占有的资源保持不放
   - 循环等待条件：发生死锁时，存在一个“进程——资源”的循环链

   <font color=red>这四个条件缺一不可</font>  

5. 死锁预防

   - 破坏“请求并保持”条件

     - 第一种协议：进程运行开始前必须申请运行过程中所有所需资源。

       简单，安全但是资源会被严重浪费。

     - 第二种协议：允许进程获得运行初期所需的资源后就开始运行，在运行过程中逐步释放分配给自己的资源。

   - 破坏“不可抢占”条件

     - 即让资源可以被抢占，但是实现很复杂，且被抢夺资源的进程很可能失去已完成的部分工作。

6. 死锁避免

   - 系统安全状态：系统按照某种顺序（<font color=blue>安全序列</font>）完成为进程分配资源进而让进程顺利进行（<font color=blue>即没有死锁</font>）

     系统处于安全状态<font color=red>一定</font>没有死锁，系统处于不安全状态<font color=blue>可能</font>有死锁也可能没有

   - 利用银行家算法避免死锁：

     - 本质即通过代码实现资源的顺序分配
     - 算法所需数据结构：
       - 可用资源数量：Available[i]
       - 最大需求矩阵：Max[i，j]
       - 分配矩阵：Allocation[i，j]
       - 需求矩阵：Need[i，j]
       - <font color=blue>Max=Allocation+Need</font>
     - 算法步骤：
       - 比较Need[0，1]与Available[1]，即第0个进程所需的第1种资源数目与可用的第一种资源数目进行比较，如果Available更大则表明第0个进程所需的第1种资源满足分配
       - 遍历第0个资源所需的所有资源种类，如果都满足分配则第0个进程可作为资源分配顺序的第一位，随后释放第0个进程的所有Allocation（<font color=blue>即Available=Need[0, ]+Allocation[0, ]</font>）；反之则遍历第1个资源至最后一个，找到资源分配顺序的第一位，释放其所有Allocation
       - 按照上述步骤直到所有的进程都进入资源分配顺序或资源不够分配为止

7. 死锁检测

   - 系统死锁可以使用资源分配图来描述
   - 死锁定理：
     - 消除P~i~的请求边和分配边，使其成为孤立节点
     - 依次完成上述步骤
     - 如果资源分配图能够变成全部都是孤立节点的图，则可完全简化，即不会出现死锁；反之，则改资源状态图对应的状态为死锁状态。

8. 死锁解除

   - 资源剥夺法：抢占足够的资源给死锁进程
   - 撤销进程法：终止死锁进程
   - 进程回退法

## 进程同步

### 进程同步基本概念

1. 两种制约关系
   - 互斥关系：间接相互制约，多程序并发执行时，共享系统资源只能互斥访问。系统需要对这些资源统一分配
   - 同步关系：直接相互制约，两个或多个进程完成同一任务而相互合作
   - 互斥关系是同步关系的一个特例
2. 临界资源
   - 需要采用互斥访问的资源称为临界资源
3. 临界区问题
   - 访问临界资源的代码称为临界区
   - 解决临界区问题需要4条准则
     - 空闲让进
     - 忙则等待
     - 有限等待：要求访问临界资源的程序，在一定的时间后能够访问临界资源，不会永久等待
     - 让权等待：当程序无法进入临界区时立刻释放处理机（信号量实现）

### 软件同步机制

- Peterson解决方案

  - 适用于两个进程（$`P_0,P_1`$）交替执行临界区的情况

  - ```c
    do{
        flag[i]=TRUE;
        turn=j;
        while(flag[i]&&turn==j);
        临界区
        flag[i]=FALSE;
        剩余区
    }while(TRUE)
    ```

  - 满足空闲让进，忙则等待，有限等待

### 硬件同步机制

实际上，在对临界区进行管理时，可以将标志看作一个锁，“锁开”进入，“锁关”等待，初始时锁是打开的。每个要进入临界区的进程，必须先对锁进行测试，当锁未开时，则必须等待，直至锁被打开。当锁打开时，则应立即把其锁上，以阻止其他进程进入临界区。显然，为防止多个进程同时测试到“锁开”，测试和关锁操作必须是连续的，不允许分开进行。

1. 关中断

   - 进入锁测试前关闭中断，直到锁测试结束后才能打开中断。这样在临界区执行期间，计算机系统不响应中断，不引发调度
   - 影响系统效率，不适合多CPU处理器

2. 利用Test-And-Set指令实现互斥

   - ```c
     boolean TS(boolean *lock){
         boolean old;
         old=*lock;
         *lock=TRUE;
         return old;
     }
     ```

     这条指令可以看成一个函数，是一条原语操作。lock=FALSE代表资源空闲，lock=TRUE代表资源被占用

   - ``` c
     do{
         ...
         while(&lock);
         临界区
         lock=FALSE;//解锁
         剩余区
     }while(true)
     ```

   - 实现简单，也适用于多处理器环境

   - 不满足让权等待

3. 利用swap指令实现进程互斥

   - ```c
     void swap(boolean *a,boolean *b){
         boolean temp;
         temp=*a;
         *a=*b;
         *b=temp;
     }
     ```

   - ```c
     do{
         key=TRUE;
         do{
             swap(&lock,&key)
         }while(key!=FALSE);
         临界区
         lock=FALSE;
         ...
     }while(TRUE)
     ```

### 信号量机制

1. 整形信号量

   - 用于表示资源数目的整形量S

   - 仅能通过两个标准原子操作访问：

     - wait(s)

     - signal(s)

     - ```c
       wait(s){
           while(s<=0);
           s--;
       }
       signal(s){
           s++;
       }
       ```

     - 不满足让权等待

2. 记录型信号量

   - 增加进程链表指针list，用于链接所有等待进程
   - ```c
     typedef struct{
         int value;
         struct PCB *list
     }semaphore
     wait(semaphore *S){
         S->value--;
         if(S->value<0)block(S->list);//该类资源分配完毕，自我阻塞并放弃处理机
     }
     signal(semaphore *S){
         S->value++;
         if(S->value<=0)wakeup(S->list)
     }
     ```

3. 信号量的应用

   - 互斥：
     - 找出临界区
     - 设置互斥信号量semaphore mutex=1
     - 临界区前P(mutex)，后V(mutex)
     - 注意：不同的临界区要设置不同的互斥信号量，P、V操作成对出现，可直接定义semaphore mutex=1而不用写繁琐的结构体
   - 同步：
     - 找出同步关系，确定前后顺序
     - 设置semaphore s=0
     - 前V P后完成代码

4. 管程

   - 概念：定义了一个数据结构和能为并发进程所执行的一组操作，这组操作能同步进程并且改变管程中的数据
   - 组成部分：
     - 管程的名称
     - 局部用于管程的共享数据结构说明
     - 对该数据结构进行的操作的一组过程
     - 对局部于管程的共享数据设置初始值的语句

5. 经典的同步问题

   - 生产者消费者问题：

     - 问题描述：在生产者和消费者之间的公用缓冲池中，具有n个缓冲区。只要缓冲池未满，生产者便可将消息送入缓冲池；只要缓冲池未空，消费者便可从缓冲池中取走一个消息。

     - ```c
       semaphore mutex=1;
       empty=n;
       full=0;
       void consumer(){
           while(1){
              P(full);
              P(mutex);//必须先同步后互斥
              remove an item from buffer;
              V(empty);
              V(mutex);
              comsume an item;
           }
       }
       void producer(){
           while(1){
               produce an item nextp;
               P(empty);
               P(mutex);
               add nextp to buffer;
               V(full);
               V(mutex);
           }
       }
       ```

   - 读者写者问题

     - 问题描述：

     - 一个数据文件或记录可被多个进程共享，我们把只要求读该文件的进程称为“reader进程”，其他进程称为“writer进程”。允许多个reader同时读，一次仅允许一个writer写，写的时候禁止其他的writer写和reader的读

     - ```c
       semaphore wmutex=1,rmutex=1;
       int readcount=0;
       void reader(void){
           while(1){
               P(rmutex);
               if(readcount==0){
                   P(wmutex);
               }
               readcount=readcount+1;
               V(rmutex);
               read_data_base();//读数据
               P(rmutex);//读者读完数据要离开，先取读者计数器互斥量
               if(readcount==0){
                   V(wmutex);
               }
               V(rmutex);
           }
       }
       void writer(void){
           while(1){
               think_up_data;//产生数据
               P(wmutex);
               write_data_base;//写入数据
               V(mutex);
           }
       }
       ```

   - 哲学家进餐问题

     - 问题描述：有5个哲学家共用1张圆桌，他们分别坐在圆桌周围的5把椅子上，在圆桌上有5个碗和5根筷子，他们的生活方式是交替地进行思考和进餐；平时，1个哲学家进行思考，其饥饿时便会试图取用左右两边最靠近自己的筷子，他只有在拿到2根筷子时才能进餐；进餐毕，放下筷子继续思考。

     - ```c

## 内存管理概述

### 内存管理概念

1. 内存管理基本概念
   - 程序占用的地址空间为作业的逻辑地址空间，即逻辑空间
   - 逻辑空间种的指令和操作数地址为逻辑地址（即cpu生成的地址）
   - 内存地址为物理地址
2. 内存管理的基本功能
   - 内存空间的分配与回收
   - 内存空间的扩充
   - 地址转换
   - 存储保护（1.使用上、下限寄存器2.使用重定位寄存器和界地址寄存器）
3. 程序的运行过程
   - 编译：源代码转换成cpu可执行的目标代码（<font color=blue>.object文件</font>）
   - 链接：将.object文件与它所需库函数链接在一起形成完整的装入模块
     - 静态链接：运行前完成，以后不拆开
     - 动态链接：
       - 装入时动态链接
       - 运行时动态链接
   - 装入：将装入模块放入内存
     - 绝对装入方式：编译时产生的地址为绝对地址（<font color=red>不使用</font>）
     - 可重定位装入方式：编译时产生相对地址，在装入时完成重定位
     - 动态运行时的装入方式：编译时产生相对地址，在装入时完成<font color=blue>动态</font>重定位

### 程序运行时内存映像与地址空间

1. 未使用区：<font color=blue>大小固定</font>
2. 只读代码段：
   - .init 程序初始化的调用的_init函数
   -  .text 用户程序的机器代码
   -  .rodata read only data
3. 读/写数据段：
   - .data 已初始化的全局变量和静态变量
   -  .bss 未初始化和所有初始化为0的全局变量与静态变量
4. 堆：用来动态分配的变量（malloc）
5. 栈：实现函数调用，<font color=red>从高地址往低地址方向生长</font>

## 连续分配管理方式

- 单一连续分配：仅有一道用户程序占据整个空间

- 固定连续分配：划分区域，每一个分区仅装入一道作业，建立分区使用表

### 动态分区分配

  1. 数据结构：
     - 空闲分区表
     - 空闲分区链（双向链表）
  2. 分配算法：
     - 首次适应算法（FF）：
       - 空闲分区链递增的次序链接；从链首查找满足大小的空闲区
       - 保留高地址大空闲区，应对以后到达的大作业
       - 低地址不断划分，留下很小的碎片
     - 循环首次适应算法（NF）：
       - 从上一次找到的空闲区开始寻找下一个满足大小的空闲区
       - 空闲区分布更均匀
       - 碎片分散到所有空间种
     - 最佳适应算法（BF）：
       - 搜索整个序列找到最适合的空闲区进行分配
       - 每次分配的空闲区最合适
       - 会留下难以利用的小空闲区
     - 最坏适应算法（WF）：
       - 搜索整个序列寻找最大分区进行分配
       - 可以减少难以利用的小碎片
       - 大空闲区被用完，算法开销很大
     - 快速适应算法（分类搜索法）:
       - 空闲分区所有大小相同的分区单独设立链表，再使用一张外部索引对应分区类型
       - 查找效率高
       - 分区归还主存时算法复杂
     - <font color=red>伙伴系统</font>
       - 空闲块大小为$`2^k`$，k取整数，申请的块放入其大小最接近的大小为$`2^k`$的块中
       - 系统初始化只有一个块，其大小为$`2^u`$
       - 如果申请的块的大小大于$`2^{s-1}`$，但是小于等于$`2^s`$，则分配块大小为$`2^s`$
       - 如果系统存在大小为$`2^s`$的块，则直接分配
       - 如果系统存在大小为$`2^{s+1}`$的块，则将该块拆成两个$`2^s`$的块，分配一个即可
       - 递归查找大小为$`2^{s+i}`$的块并精心分割即可

## 基本分页存储管理

### 简单分页存储管理

  1. 页面与物理块

     - 页面：地址空间被分成若干个页，每页加以编号；相应的分成若干块
     - 页面大小：页面过小可以减少内部碎片，会造成页表过长；页面过大会减少页表长度，但是碎片会变大。因此要选择合适大小的页面

  2. 地址结构：

     | 31    | 12   | 11      | 0    |
     | ----- | ---- | ------- | ---- |
     | 页号P |      | 偏移量W |      |

     图中地址长度为32位，0\~11位为页内地址，即每页大小为$`2^{11}`$B，等于4KB；12\~31位为页号
  
  3. 给定逻辑地址空间中的地址A，页面大小为L，则有：$`P=int[\frac{A}{L}]`$ $`d`$=[A]MOD$`L`$ ；其中$`P`$为页号，$`d`$为页内地址
  
  4. 在分页系统中，允许进程的各个页离散的存储在内存的任意物理块中
     页表：操作系统为每个进程生成一张页表，用来记录进程每一页在内存中的物理块号，通常放在内存。<font color=red>页表仅存放块号，每个进程有自己页表基址寄存器（页表序号）</font>
     页表长度=页表项个数$`\times`$页表项大小
  
  5. 地址变换机构
  
     - 基本的地址变换机构：
     
       - 分页地址变换机构自动将有效页号和页内地址两个部分，再用页号为索引去检索页表。
       - 页号大于等于页表长度，则访问的地址超越程序的地址空间，产生地址越界中断。
       - 未出现越界错误，则页表起始地址$`+`$页号$`\times`$页表项长度获得该表项在页表中位置，获得该页的物理块号，装入物理地址寄存器中。同时将有效地址寄存器中的页内地址送入物理地址寄存器中的块内地址段，得到完整的物理地址。
     
     - 具有快表的地址变换机构：
     
       - 为提高地址变换速度，可在地址变换机构中增设一个快表（TLB），用来存放当前访问的那些页表项。
       
       - 页号先与快表比较，若匹配失败，则再访问内存中的页表。
       
       - 访问的有效时间：$`EAT=a\times\lambda+(t+\lambda)(1-a)+t=2t+\lambda-at`$
       
         $`\lambda`$表示查找快表所需时间，$`a`$表示命中率，$`t`$表示访问一次内存所需要的时间
