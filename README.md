## 死锁

### 死锁的概念

1. 资源问题：

   - 可重用资源与消耗性资源
   - 可抢占资源与不可抢占资源

2. 计算机系统中的死锁

   - 竞争不可抢占资源引发的死锁
   - 竞争可消耗性资源引发的死锁
   - 进程推进顺序不当引发的死锁

3. 死锁的定义

   - 多个进程因竞争资源而造成的一种僵局，若无外力作用，这些进程都无法继续向前推进

4. 产生死锁的条件

   - 互斥条件：某种资源只能被一个进程占用，其他进程想使用只能等到该资源释放（<font color=red>不可被改变</font>）
   - 不剥夺（不抢占）条件：进程获得资源在执行过程中不能被别的进程抢占资源，只能在该进程结束后自动释放资源
   - 请求并保持条件：进程占有至少一个资源后还提出新的资源请求，而请求的资源被另一个程序占用，此时请求进程被阻塞，同时进程对自己占有的资源保持不放
   - 循环等待条件：发生死锁时，存在一个“进程——资源”的循环链

   <font color=red>这四个条件缺一不可</font>  

5. 死锁预防

   - 破坏“请求并保持”条件

     - 第一种协议：进程运行开始前必须申请运行过程中所有所需资源。

       简单，安全但是资源会被严重浪费。

     - 第二种协议：允许进程获得运行初期所需的资源后就开始运行，在运行过程中逐步释放分配给自己的资源。

   - 破坏“不可抢占”条件

     - 即让资源可以被抢占，但是实现很复杂，且被抢夺资源的进程很可能失去已完成的部分工作。

6. 死锁避免

   - 系统安全状态：系统按照某种顺序（<font color=blue>安全序列</font>）完成为进程分配资源进而让进程顺利进行（<font color=blue>即没有死锁</font>）

     系统处于安全状态<font color=red>一定</font>没有死锁，系统处于不安全状态<font color=blue>可能</font>有死锁也可能没有

   - 利用银行家算法避免死锁：

     - 本质即通过代码实现资源的顺序分配
     - 算法所需数据结构：
       - 可用资源数量：Available[i]
       - 最大需求矩阵：Max[i，j]
       - 分配矩阵：Allocation[i，j]
       - 需求矩阵：Need[i，j]
       - <font color=blue>Max=Allocation+Need</font>
     - 算法步骤：
       - 比较Need[0，1]与Available[1]，即第0个进程所需的第1种资源数目与可用的第一种资源数目进行比较，如果Available更大则表明第0个进程所需的第1种资源满足分配
       - 遍历第0个资源所需的所有资源种类，如果都满足分配则第0个进程可作为资源分配顺序的第一位，随后释放第0个进程的所有Allocation（<font color=blue>即Available=Need[0, ]+Allocation[0, ]</font>）；反之则遍历第1个资源至最后一个，找到资源分配顺序的第一位，释放其所有Allocation
       - 按照上述步骤直到所有的进程都进入资源分配顺序或资源不够分配为止

7. 死锁检测

   - 系统死锁可以使用资源分配图来描述
   - 死锁定理：
     - 消除P~i~的请求边和分配边，使其成为孤立节点
     - 依次完成上述步骤
     - 如果资源分配图能够变成全部都是孤立节点的图，则可完全简化，即不会出现死锁；反之，则改资源状态图对应的状态为死锁状态。

8. 死锁解除

   - 资源剥夺法：抢占足够的资源给死锁进程
   - 撤销进程法：终止死锁进程
   - 进程回退法

## 进程同步

### 进程同步基本概念

1. 两种制约关系
   - 互斥关系：间接相互制约，多程序并发执行时，共享系统资源只能互斥访问。系统需要对这些资源统一分配
   - 同步关系：直接相互制约，两个或多个进程完成同一任务而相互合作
   - 互斥关系是同步关系的一个特例
2. 临界资源
   - 需要采用互斥访问的资源称为临界资源
3. 临界区问题
   - 访问临界资源的代码称为临界区
   - 解决临界区问题需要4条准则
     - 空闲让进
     - 忙则等待
     - 有限等待：要求访问临界资源的程序，在一定的时间后能够访问临界资源，不会永久等待
     - 让权等待：当程序无法进入临界区时立刻释放处理机（信号量实现）

### 软件同步机制

- Peterson解决方案

  - 适用于两个进程（$`P_0,P_1`$）交替执行临界区的情况

  - ```c
    do{
        flag[i]=TRUE;
        turn=j;
        while(flag[i]&&turn==j);
        临界区
        flag[i]=FALSE;
        剩余区
    }while(TRUE)
    ```

  - 满足空闲让进，忙则等待，有限等待

### 硬件同步机制

实际上，在对临界区进行管理时，可以将标志看作一个锁，“锁开”进入，“锁关”等待，初始时锁是打开的。每个要进入临界区的进程，必须先对锁进行测试，当锁未开时，则必须等待，直至锁被打开。当锁打开时，则应立即把其锁上，以阻止其他进程进入临界区。显然，为防止多个进程同时测试到“锁开”，测试和关锁操作必须是连续的，不允许分开进行。

1. 关中断

   - 进入锁测试前关闭中断，直到锁测试结束后才能打开中断。这样在临界区执行期间，计算机系统不响应中断，不引发调度
   - 影响系统效率，不适合多CPU处理器

2. 利用Test-And-Set指令实现互斥

   - ```c
     boolean TS(boolean *lock){
         boolean old;
         old=*lock;
         *lock=TRUE;
         return old;
     }
     ```

     这条指令可以看成一个函数，是一条原语操作。lock=FALSE代表资源空闲，lock=TRUE代表资源被占用

   - ``` c
     do{
         ...
         while(&lock);
         临界区
         lock=FALSE;//解锁
         剩余区
     }while(true)
     ```

   - 实现简单，也适用于多处理器环境

   - 不满足让权等待

3. 利用swap指令实现进程互斥

   - ```c
     void swap(boolean *a,boolean *b){
         boolean temp;
         temp=*a;
         *a=*b;
         *b=temp;
     }
     ```

   - ```c
     do{
         key=TRUE;
         do{
             swap(&lock,&key)
         }while(key!=FALSE);
         临界区
         lock=FALSE;
         ...
     }while(TRUE)
     ```

### 信号量机制

1. 整形信号量

   - 用于表示资源数目的整形量S

   - 仅能通过两个标准原子操作访问：

     - wait(s)

     - signal(s)

     - ```c
       wait(s){
           while(s<=0);
           s--;
       }
       signal(s){
           s++;
       }
       ```

     - 不满足让权等待

2. 记录型信号量

   - 增加进程链表指针list，用于链接所有等待进程

## 内存管理概述

### 内存管理概念

1. 内存管理基本概念
   - 程序占用的地址空间为作业的逻辑地址空间，即逻辑空间
   - 逻辑空间种的指令和操作数地址为逻辑地址（即cpu生成的地址）
   - 内存地址为物理地址
2. 内存管理的基本功能
   - 内存空间的分配与回收
   - 内存空间的扩充
   - 地址转换
   - 存储保护（1.使用上、下限寄存器2.使用重定位寄存器和界地址寄存器）
3. 程序的运行过程
   - 编译：源代码转换成cpu可执行的目标代码（<font color=blue>.object文件</font>）
   - 链接：将.object文件与它所需库函数链接在一起形成完整的装入模块
     - 静态链接：运行前完成，以后不拆开
     - 动态链接：
       - 装入时动态链接
       - 运行时动态链接
   - 装入：将装入模块放入内存
     - 绝对装入方式：编译时产生的地址为绝对地址（<font color=red>不使用</font>）
     - 可重定位装入方式：编译时产生相对地址，在装入时完成重定位
     - 动态运行时的装入方式：编译时产生相对地址，在装入时完成<font color=blue>动态</font>重定位

### 程序运行时内存映像与地址空间

1. 未使用区：<font color=blue>大小固定</font>
2. 只读代码段：
   - .init 程序初始化的调用的_init函数
   -  .text 用户程序的机器代码
   -  .rodata read only data
3. 读/写数据段：
   - .data 已初始化的全局变量和静态变量
   -  .bss 未初始化和所有初始化为0的全局变量与静态变量
4. 堆：用来动态分配的变量（malloc）
5. 栈：实现函数调用，<font color=red>从高地址往低地址方向生长</font>

## 连续分配管理方式

- 单一连续分配：仅有一道用户程序占据整个空间

- 固定连续分配：划分区域，每一个分区仅装入一道作业，建立分区使用表

### 动态分区分配

  1. 数据结构：
     - 空闲分区表
     - 空闲分区链（双向链表）
  2. 分配算法：
     - 首次适应算法（FF）：
       - 空闲分区链递增的次序链接；从链首查找满足大小的空闲区
       - 保留高地址大空闲区，应对以后到达的大作业
       - 低地址不断划分，留下很小的碎片
     - 循环首次适应算法（NF）：
       - 从上一次找到的空闲区开始寻找下一个满足大小的空闲区
       - 空闲区分布更均匀
       - 碎片分散到所有空间种
     - 最佳适应算法（BF）：
       - 搜索整个序列找到最适合的空闲区进行分配
       - 每次分配的空闲区最合适
       - 会留下难以利用的小空闲区
     - 最坏适应算法（WF）：
       - 搜索整个序列寻找最大分区进行分配
       - 可以减少难以利用的小碎片
       - 大空闲区被用完，算法开销很大
     - 快速适应算法（分类搜索法）:
       - 空闲分区所有大小相同的分区单独设立链表，再使用一张外部索引对应分区类型
       - 查找效率高
       - 分区归还主存时算法复杂
     - <font color=red>伙伴系统</font>
       - 空闲块大小为$2^k$，k取整数，申请的块放入其大小最接近的大小为$2^k$的块中
       - 系统初始化只有一个块，其大小为$`2^u`$
       - 如果申请的块的大小大于$`2^{s-1}`$，但是小于等于$`2^s`$，则分配块大小为$`2^s`$
       - 如果系统存在大小为$`2^s`$的块，则直接分配
       - 如果系统存在大小为$`2^{s+1}`$的块，则将该块拆成两个$`2^s`$的块，分配一个即可
       - 递归查找大小为$`2^{s+i}`$的块并精心分割即可

## 基本分页存储管理

### 简单分页存储管理

  1. 页面与物理块

     - 页面：地址空间被分成若干个页，每页加以编号；相应的分成若干块
     - 页面大小：页面过小可以减少内部碎片，会造成页表过长；页面过大会减少页表长度，但是碎片会变大。因此要选择合适大小的页面

  2. 地址结构：

     | 31    | 12   | 11      | 0    |
     | ----- | ---- | ------- | ---- |
     | 页号P |      | 偏移量W |      |

     图中地址长度为32位，0\~11位为页内地址，即每页大小为$`2^{11}`$B，等于4KB；12\~31位为页号
  
  3. 给定逻辑地址空间中的地址A，页面大小为L，则有：$`P=int[\frac{A}{L}]`$ $`d`$=[A]MOD$`L`$ ；其中$`P`$为页号，$`d`$为页内地址
  
  4. 在分页系统中，允许进程的各个页离散的存储在内存的任意物理块中
     页表：操作系统为每个进程生成一张页表，用来记录进程每一页在内存中的物理块号，通常放在内存。<font color=red>页表仅存放块号，每个进程有自己页表基址寄存器（页表序号）</font>
     页表长度=页表项个数$`\times`$页表项大小
  
  5. 地址变换机构
  
     - 基本的地址变换机构：
     
       - 分页地址变换机构自动将有效页号和页内地址两个部分，再用页号为索引去检索页表。
       - 页号大于等于页表长度，则访问的地址超越程序的地址空间，产生地址越界中断。
       - 未出现越界错误，则页表起始地址$`+`$页号$`\times`$页表项长度获得该表项在页表中位置，获得该页的物理块号，装入物理地址寄存器中。同时将有效地址寄存器中的页内地址送入物理地址寄存器中的块内地址段，得到完整的物理地址。
     
     - 具有快表的地址变换机构：
     
       - 为提高地址变换速度，可在地址变换机构中增设一个快表（TLB），用来存放当前访问的那些页表项。
       
       - 页号先与快表比较，若匹配失败，则再访问内存中的页表。
       
       - 访问的有效时间：$`EAT=a\times\lambda+(t+\lambda)(1-a)+t=2t+\lambda-at`$
       
         $`\lambda`$表示查找快表所需时间，$`a`$表示命中率，$`t`$表示访问一次内存所需要的时间
  
  6. 两级页表和多级页表
  
     -
